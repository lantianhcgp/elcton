## 3. 用户授权与已配对设备

### S6：用户授权是独立层，不等同申请已批准

官方正文：<https://developer.huawei.com/consumer/cn/doc/connectivity-Guides/requesting-user-authorization-0000001050819181>  
更新时间：2026-10-10 07:04；本次 Exa 全文和官网正文 API 均成功。

> 为保护用户隐私，Wear Engine的API需要用户授权才可以正常访问。

> 若用户的运动健康App版本为11.0.3.512及以上，且对第三方应用未进行过授权操作，则消息通知NOTIFY、设备基础信息DEVICE_MANAGER将默认授予第三方应用。建议在请求用户授权前，先使用该接口查询应用是否已有相关权限。

> 请确保权限已在申请Wear Engine服务中审批通过，否则会遇到错误码为8的提示。

> 当用户允许后才能正常使用接口，否则会遇到错误码为9的提示。

官方调用序列：

```java
AuthClient authClient = HiWear.getAuthClient(this);
authClient.checkPermission(Permission.DEVICE_MANAGER);
// false 时再请求；不能将 Task<Void> 成功当作用户已允许。
authClient.requestPermission(authCallback, Permission.DEVICE_MANAGER);
```

原文：

> onOk的回调返回用户授权的权限列表；onCancel表示取消授权。

实施核对：`checkPermission` 成功且 true，或 `onOk` 的列表确有 `DEVICE_MANAGER` 后，再查设备；`onCancel`／Task failure 进入明确失败状态。没有弹窗不必然是失败，可能权限默认已授予；反过来没有弹窗也不是审批／签名正确的证明。

### S7：查询已配对设备和连接状态

官方正文：<https://developer.huawei.com/consumer/en/doc/connectivity-Guides/device-connection-management-0000001050779152>（本次英文全文）及同 ID 中文官网正文 API（本次成功）。


解绑重绑后 UUID 可能变化，旧缓存可能返回 `ERROR_CODE_DEVICE_UUID_IS_INVALID`，官方建议重新 `getBondedDevices()`。要取所有 Wear Engine 能力设备可用 `getCommonDevice()`，但其中可能没有 P2P 能力；`getP2pCapability()` 返回 0 支持／1 不支持／2 未知。**获取设备列表成功不证明表应用已安装、在线或双方指纹匹配。**

所指方法是 `DeviceClient.hasAvailableDevices()`，仅返回是否有可用 Wear Engine 设备；不要把“不需授权”扩大到 `getBondedDevices()` 或 P2P。

### S8：权限分类

官方正文：<https://developer.huawei.com/consumer/cn/doc/connectivity-References/permission-0000001059433005>  
本次全文已读。

> DEVICE_MANAGER … 手机侧应用和穿戴设备侧应用双向传输消息和文件。

> 当使用DeviceClient、P2pClient、MonitorClient相关的API时，需要申请该权限。

- `DEVICE_MANAGER`：设备基础信息＋P2P；此课表同步的最低 Wear Engine Scope。
- `NOTIFY`：NotifyClient 模板化通知，非 P2P 文本收发。
- `WEAR_USER_STATUS`：佩戴状态与心率告警，不是 Android `USER_STATUS`。
- `DEVICE_SN`：取 SN；若同步只用返回的 Device，不必为了标识设备额外取 SN。
- `MOTION_SENSOR`／`SENSOR`：传感器业务，不是同步课表前置。

### S10：消息与文件 API、大小、接收目录

原文：

> 消息长度大小的限制为1KB。针对消息长度超过限制的情况可以采用发送文件（文件大小不超过100MB）的方式或进行消息分包控制。

官网消息 API：

```java
Message.Builder builder = new Message.Builder();
builder.setPayload(messageStr.getBytes(StandardCharsets.UTF_8));
Message sendMessage = builder.build();
P2pClient p2pClient = HiWear.getP2pClient(this);
p2pClient.setPeerPkgName(peerPkgName);
p2pClient.setPeerFingerPrint(peerFingerPrint);
p2pClient.send(connectedDevice, sendMessage, sendCallback);
```

官网文件 API：

```java
File sendFile = new File(filePath);
Message.Builder builder = new Message.Builder();
builder.setPayload(sendFile);
Message fileMessage = builder.build();
p2pClient.send(connectedDevice, fileMessage, sendCallback);
```

原文代码注释：

> resultCode为207表示消息发送成功，其他表示消息发送失败。

`Task` 的 `addOnSuccessListener`、`SendCallback.onSendResult(207)`、表应用业务 ACK 是不同层：官方给的是发送任务／发送结果；**表端已校验并落盘课表**需要自有 ACK，不能仅由任务成功推出。

- 消息按实际 UTF-8 **字节**控制，不按中文字符数。官方写 1KB，不在此擅自推定 K 的所有边界换算。
- 接收用 `registerReceiver(connectedDevice, receiver)`，`Receiver.onReceiveMessage(Message)` 区分 `MESSAGE_TYPE_DATA`／`MESSAGE_TYPE_FILE`。

原文：

> 文件会保存在“/data/data/{三方应用包名}/files/WearEngine”路径下。

> 若开发者集成的SDK版本为5.0.0.301及以下……只能接收点对点消息。若集成的SDK版本是5.0.1.300及以上，则还可以接收文件。

> 手机应用发送文件给穿戴设备应用时收到错误码10（ERROR_CODE_INVALID_FILE），请检查手机侧应用是否有相关文件的访问权限。

取消接收须 `unregisterReceiver(receiver)`。文件完成后再校验／应用；读取期间不要将进度回调或收到路径直接当完整业务成功。

### S13：原生 API 的真实参数与数据形状

已下载的官方 `wearengine.js`：

```js
import wearengine from "@system.wearengine";
var WEARENGINE_SERVICE_VISION_302 = 302;
var WEARENGINE_SERVICE_VISION_303 = 303;
var WEARENGINE_SERVICE_VISION_401 = 401;
var WEARENGINE_SDK_VERSION = "3";
```

| 原生调用 | 官方 SDK 实际参数 | 对本项目的意义 |
|---|---|---|
| `getWearEngineVersion` | `{ complete: getVersionCallBack, sdkVersion: "3" }` | 官方包装初始化会做版本协商；返回字符串最后一段被用作 302／303／401 分支，不是 Android SDK 版本 |
| `setPackageName` | `{ appName: peerPkgName, complete, fail }` | `peerPkgName` 是手机包 `com.hcbiu.elcton`，不是表 bundleName |
| `setFingerprint` | `{ appName: this.peerPkgName, appCert: fingerPrint, complete, fail }` | `appCert` 是手机 SHA-256，不带冒号；不是 APP ID，也不是表指纹 |
| `sendMsg` | `{ deviceId: "remote", bundleName: this.peerPkgName, abilityName: "", message: message.getData(), success, fail }` | `remote` 是官方源码字面值；不是 Device UUID。bundleName 是手机包 |
| `subscribeMsg` | `{ success: successCallBack, fail: receiver.onFailure }`（官方先 `unsubscribeMsg()` 清旧订阅） | 不带 Android Device、APP ID 或 peer 参数，前面设置手机身份 |
| `unsubscribeMsg` | 无参 | 页面／应用销毁取消订阅 |
| `uploadFile` | `{ fileName, filePath: this.peerPkgName, peerPackageName: this.peerPkgName, success, fail, progress }` | `fileName` 是真实表文件路径；`filePath` 名称容易误导，但官方源码这里确实传手机包名 |
| `detect` | `{ bundleName: this.peerPkgName, success, fail }` | 官方包装的手机 APP 安装检测；不等同 Android ping 的表在线判定 |

原生消息真实源码片段（行 298–306）：

```js
if (this.version >= WEARENGINE_SERVICE_VISION_401) {
  wearengine.sendMsg({
    deviceId: "remote",
    bundleName: this.peerPkgName,
    abilityName: "",
    message: message.getData(),
    success: successCallBack,
    fail: failCallBack
  });
}
```

官方接收包装源码（行 220–245）表明：

- `data.isRegister` 为注册完成，不是业务消息；没有 data 的回调也作为注册成功。
- 原生文件回调带 `data.isFileType` 与 **`data.file`**，包装转换为 `{ isFileType:true, name:data.file, mode:"", mode2:"" }`。
- 原生文本回调从 **`data.message`** 取文本，包装后的 `onReceiveMessage` 直接得到字符串。
- 调原生 API 的业务不能把官方包装层的 `name`／字符串形状不加转换地套到原生回调。

官方源码版本分支：`setFingerprint`／上传文件先检查最后段 ≥302；`setPackageName` 先检查 ≥303；源码英文注释明确 `Service version earlier than 303 does not support the internal://app/ directory`。≥401 时 `detect`／`sendMsg`／`subscribeMsg`／`unsubscribeMsg` 走 `wearengine`；更旧分支走 `FeatureAbility`。**这些是官方包装策略，不是 Lite HarmonyOS API level 或完整固件号的通用换算表。**

当前项目 `wearChannel.js` 直接使用原生 API，没有调用官方包装的 `getWearEngineVersion({sdkVersion:"3"})` 初始化，也没有旧版本 FeatureAbility 分支。应记录目标真机返回的完整 Wear Engine 服务版本及原生支持性；本报告不宣称缺这个调用一定导致失败。

### S14：Lite 接入指南的身份、大小、前台与版本边界

官方 JS 指南：<https://developer.huawei.com/consumer/cn/doc/connectivity-Guides/send-message-0000001052460491>  
更新时间：2026-10-10 00:06；本次全文与官网正文 API 均成功。

> 指定需要通信的手机侧应用指纹SHA256信息……指纹信息中不带冒号，指纹设置为手机侧应用在开发者联盟申请账号服务时注册的指纹之一。

> 消息长度大小的限制为1KB。针对消息长度超过限制的情况可以采用发送文件（文件大小不超过4MB）的方式或进行消息的分包控制。

> 由于轻量级智能穿戴设备不支持同类型文件并行传输，向手机传输文件时，在当前文件传输完成之前，不要发送另一文件，否则会直接返回失败。

> 接收到的文件将存储在应用私有目录“internal://app/”下。

> 建议在第三方应用的onDestroy生命周期里或之前调用unregisterReceiver方法，以释放服务端资源。

**注意传输方向**：Android→表的官方上限说明是 100MB；Lite→手机指南写不超过 4MB，细分步骤又写“文件大小要小于4M”。最小探针应远小于上限，不以边界值验证，不能把两个方向限制混写成一个双向上限。

版本文档本身有两个表述，均原样记录，不猜固件换算：

- 当前 JS 指南：“轻量级智能穿戴设备系统 HarmonyOS 2.0以下版本不支持调用setPeerFingerPrint方法”。
- API 参考 <https://developer.huawei.com/consumer/cn/doc/connectivity-References/point-to-point-message-0000001052164296>（本次全文、官网 API 均成功）：“轻量级智能穿戴设备系统10.1.3.28以下版本不支持调用setPeerFingerPrint方法”。

旧版需在 `config.json` 的 `module.metaData.customizeData` 配置 `supportLists`，value 由**手机包名:手机指纹**构成，最长支持 255。不要拿此冒号分隔符误解成 SHA256 内部要加冒号。

JS 指南对拉起表端区分明确：

> 如果穿戴设备JS应用的deviceType属性配置包含liteWearable……无需其他额外配置，在手机侧调用ping方法，即可拉起穿戴设备侧应用。

只有 `deviceType` **仅 wearable** 的 JS 智能穿戴分支才要求 `HiWearMainAbility.java`。本项目 Lite 不应照抄这项 Java Ability。
