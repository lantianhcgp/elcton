# 课程表同步 · fetch 可达性探测（四轮真机实测结论）

> 目的：做手机↔手表课表同步之前，钉死一个事实 —— **FIT3 走蓝牙借手机网时，
> 手表的 `@system.fetch` 到底能打到哪里**。结论决定同步走零部署的局域网直连，
> 还是走云中转（手机 POST 上云、手表 HTTPS 拉取）。

## 怎么跑

1. 手机起测试服务：`python3 tools/lan-server.py 8123`（监听 0.0.0.0，打印每个请求的来源 IP）
2. **核对手机当前内网地址**（会变）：`ifconfig wlan1` —— 地址过期必然 `-6`
3. 手表 App → 底栏 **同步** → 自动串行跑 6 条探测；点行看原始错误码
4. 对照手机：`[HIT] <手表来源IP>:<port> -> /t.json` 才是硬证据（不依赖手表自报）

## 探测项（v6 现行）

| # | 探测 | 作用 |
|---|------|------|
| 1 | `http://223.5.5.5/` | 纯 IP、不走 DNS —— 分清「DNS 坏」还是「整条路由坏」 |
| 2 | `http://www.qq.com/` | 域名 + 明文 HTTP 路径 |
| 3 | `https://www.baidu.com/` | 域名 + TLS 路径 |
| 4 | `https://ws.fseatech.cn/` | 签到 app 的服务器 = 云中转路线 B 的真实端点 |
| 5 | `http://192.168.45.224:8123/t.json` | 手机内网 = 路线 A；带 `lanok` 才算真通 |
| 6 | `http://127.0.0.1:8123/t.json` | 阴性对照：表上的回环是**表自己**，永远 `-6` |

## 四轮实测证据

| 轮次 | 结果 |
|------|------|
| 1 | 公网 HTTP 拿到过 `204`；内网 `-6`；`lan-server` 零命中 |
| 2 | `44.1/49.1`（网关猜测）全 `-6` → 砍掉；`-6/-9` 无官方码表，只能带原始 `data` |
| 3 | `-6`（内网，秒拒）、`-9 data=HttpRequest Processing`（HTTPS，~130ms）、公网 HTTP 挂到看门狗；`lan-server` 仍零命中；手机侧同期挂着 `tun0` fake-IP 代理 |
| 4（终轮） | **签到服 HTTPS → `200`**、百度 HTTPS → `200`（间歇）、**`223.5.5.5` → `404`**（真实响应 = 纯 IP HTTP 也通）、`192.168.1.200 → -6`（地址已过期，手机现为 `192.168.45.224`）、`127.0.0.1 → -6`（设计内阴性） |

## 判读结论（终版，2026-10-09 第五轮后拍板）

1. **路线 A（手机内网）已证伪**。第五轮在「手机 IP 正确 `192.168.1.199` + `lan-server`
   自检 200 + 代理已关（tun0 消失）」三个条件下重测，两条内网探针仍 `-6`，
   **带时间戳的服务端日志整个探测窗口零请求**——包在手表侧就被拒了，根本没到手机。
   加上网关候选 `192.168.44.1/49.1` 历史轮次同样 `-6`，判定：**表借手机网不给回包**。
2. **路线 B（云中转）成立**：签到服 HTTPS **四轮全 200**，`223.5.5.5` 每轮真实 404
   （纯 IP HTTP 也通），域名解析/TLS/HTTP 全链路实测通过。第 3 轮的 `-6/-9` 归因
   手机侧代理/VPN 对蓝牙借网流量的干扰（关代理后百度从 `-9` 变 `200` 是直接对照）。
3. **大页面不稳定**（百度/qq 反复在 `-9`/超时/-76 之间跳），成功/失败按响应体大小分。
   课表 JSON 只有 2~5KB，属「通」的那一类 → **同步采用云端中转，端点见 `sync-endpoint.md`**。
4. **`@system.fetch` 不声明权限也完全可用** —— Lite 不写 `reqPermissions` 的前提下，
   联网能力实测正常（这条本身就是一个结论）。

## 已修缺陷（v6）

- **重测闪退**：`onRun` 无互斥，上一轮未结束时重测会开第二条链，两链并发 fetch
  （Lite 并发 fetch 已知会挂/崩）。修：`running` 互斥 + `gen` 代际守卫丢弃过期回调
  + 链尾/销毁推进代际。
- **回调内异常抛进平台代码**：`brief()` 里 `JSON.stringify` 对循环引用/function
  返回 `null/undefined`，紧接 `.length` 即 TypeError，而 success/fail 回调体原本
  没包 try。修：`brief` 结果类型兜底 + `finish` 与两个回调全包 try/catch +
  `setStatus` 越界保护。

## 相关实现

- 探测页：`entry/src/main/js/MainAbility/pages/sync/`（串行队列 + 10s 看门狗，
  参照签到 app 实测经验：lite 并发 fetch 会卡死、回调可能不回来）
