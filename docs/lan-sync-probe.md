# 课程表同步 · 局域网可达性探测（前置实测）

> 目的：在做手机↔手表课表同步之前，先钉死一个事实——**FIT3 走蓝牙借手机网时，
> 手表的 `@system.fetch` 能不能打到手机的内网地址**。通 → 走零部署的局域网直连；
> 不通 → 只能走云中转（手机 POST 上云、手表 HTTPS 拉取）。

## 怎么跑

1. 手机（本机）起测试服务：
   ```bash
   python3 tools/lan-server.py 8123        # 监听 0.0.0.0，打印每个请求的来源 IP
   ```
2. 查手机内网地址：`ip -4 addr show wlan0`（本次实测 `192.168.1.200`）
3. 装好带「同步」入口的课程表 → 首页底栏点 **同步** → 页面自动跑 4 条探测
4. 结果两处对照：
   - 表上：每行 `✓ 通` / `✗ 失败 错误码` / `超时 6s`，底部一行响应详情
   - 手机：服务打印 `[HIT] <手表来源IP>:<port> -> /t.json`（能直接看出手表的子网）

## 探测项

| # | 探测 | 期望 | 说明 |
|---|------|------|------|
| 1 | `http://192.168.1.200:8123/t.json` | 通 = 走 Wi-Fi 内网可行 | 手机 wlan0 的地址（会变，跑前 `ifconfig wlan0` 核对） |
| 2 | `http://192.168.44.1:8123/t.json` | 通 = 走 BLE 网关可行 | Android/HarmonyOS 蓝牙共享常见网关，**不依赖 Wi-Fi** |
| 3 | `http://192.168.49.1:8123/t.json` | 通 = 走热点网关可行 | 热点/Wi-Fi Direct 常见网关 |
| 4 | `http://127.0.0.1:8123/t.json` | 失败 | 对照：手表上的 127.0.0.1 是手表自己 |
| 5 | `http://connect.rom.miui.com/generate_204` | 通 | 对照：网络本身（蓝牙借网）通不通 |
| 6 | `https://ws.fseatech.cn/` | 通 | 对照：HTTPS 通不通（云中转路线的前提） |

> 1-3 都带 `lanok` 字样才算真取到内容；哪条通就用哪个地址做同步端点。
> 手机没连 Wi-Fi 时 1 必然失败，此时看 2/3 —— 它们才是「任何时候都能用」的那条。

## 判读

- 1 通 → 局域网直连路线成立（零部署，手机跑 `lan-server.py` 即可）
- 1 失败但 3 通 → 网络是通的、只是到不了手机内网 → 走云中转
- 3、4 都失败 → 表侧根本没网或 `@system.fetch` 不可用（看详情行错误码）
- 详情里出现 `@system.fetch 加载失败` → Lite 不声明权限时 fetch 是否可用这条本身就有了答案
