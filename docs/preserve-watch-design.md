# 手表端同步功能：保留原设计

## 用户纠正与范围

用户明确要求：「你别把我原来的设计改了呀，只要做同步页面不就好了，我指的是手表端」。本修复只作用于手表；手机端源码与 APK 不变。

原设计基线固定为同步开发前的提交：9df5c2fd0b51053ac0ad32e42d3c2f3cf5b6f510。
上一轮跨页面改版的回滚点：37719275824c603dc336e6d2d56465294186256e；本地备份分支 backup/expanded-watch-ui-3771927。修复独立分支 fix/preserve-watch-design，不动 master。

## 接受条件

1. 原首页、周视图、详情/删除确认、取件码键盘、取件码同步页的 HML 和 CSS 与基线逐字节一致；保留字号、颜色、卡片、星期标签、单双周胶囊及底部导航，不为新增同步修改旧布局。
2. 原周视图的「同步」仍进入原同步页；原同步页保留四条已有操作及原顺序，仅在同一列表末尾添加「手机同步」入口。入口可滚动访问，不修改列表或底栏尺寸。
3. 新手机同步页单独注册、单独使用运行时屏幕信息；连接、接收、保存、失败、取消、覆盖确认和回传状态均局限于该页。返回进入原同步页。
4. 原页面只保留不可见的安全接线：同步后缓存刷新、过期回调隔离、限次数表冠补焦、删除/保存去重。不得为这些逻辑更换 HML/CSS 或显示新地点/节次行。
5. 已开始的文件提交不能被新入口打断；只在待机或连通自检状态切页，切页时取消自检定时器和旧 UI 回调。
6. 手机主编辑、手表查看/本地删除/向手机回传显式预览导入的业务不变；不新增云同步、后台常驻、其他 OS 或原页面重设计。
7. 用真实构建原始 .app 进行原设计对照和同步回归；新页单独做五窗口验证。旧页面在其他尺寸上的既有布局限制不以重新设计来消除，不借恢复版扩大兼容性声明。
8. 最终签名 HAP 的版本、身份和资源与被测原始 .app 对账；未验的真机授权、蓝牙、原生文件 I/O 和 JerryScript 低堆明确列为未验。旧 1.1.9 包仅作为历史证据，不再推荐安装，不删除手机存储中的旧文件。

## 回归条件替换

旧 watchUi 布局等待和最窄屏键盘缩小提示的验收条件来自已撤销的跨页面改版，已用原设计字节对账、原提示文案、原列表挂载焦点和异步安全回归替换。协议、事务、文件、取消和幂等测试继续运行，不能拿旧改版报告代替本恢复版本的执行结果。
