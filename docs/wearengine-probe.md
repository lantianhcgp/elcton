# Wear Engine 同步探针（首阶段）

本分支是隔离开发，不替换 master。基线为 feat/lan-sync-probe，保留现有取件码与课程查看/删除。

## 使用路径

手表：主页 → 周视图 → 同步 → 开始接收。手机：结构化课表页粘贴 elcton.schedule v1 JSON → 校验保存 → 设备页授权、查询、选中设备 → 等待 READY → 主动确认发送。

仅收到匹配传输的 APPLIED 才算成功。读回失败、缺包、旧版本和取消不报告成功。手机主编辑，表端本地修改标记冲突；探针阶段提供确认替换，完整导出回传仍未实现。

## 测试与编译

本机逻辑测试：node --test tests/*.test.mjs（simulatorFile 测试需要相邻独立 elcton-sim-qa）。CI 只运行无需模拟器目录的测试，用 GitHub Actions 编译真实 .app/HAP。

朋友 kqakqakqa 的 hmlwsim 测试副本独立，补 file.get/UTF-8 分块偏移。模拟通信与真实通信严格分开；V8 不证明真机堆、签名、蓝牙、授权与存储原子性。

## 限制与阶段边界

- 当前接收器仅同步页前台启用，未实现自动拉起后任意页接收。
- 设备目标为尽可能支持 Wear Engine/P2P 与 App 安装的设备；本阶段是 Lite 路线，其他运行时独立包和低堆变体仍未实现。
- 首阶段接收安全预算 8192 ASCII 字节；分日懒加载和大课表接收为后续工作，不截断用户数据。
- 调试签名 profile 绑定 FIT3，不是通用分发资格。
- 控制台指纹登记、审核状态和真实通信仍需验证。
- 不生成私人课表 fixture，不默认记录课表全文。

## 可靠性

两份快照槽 + 校验提交记录，先非活动槽保存和回读，后提交。提交完成后数据页面重新加载；合法空表不回填 DEMO。阶段超时、取消与代次隔离保证旧回调不重新追加；正式提交开始后的物理写入不能视为可撤回事务，需要重连查询最终状态。
