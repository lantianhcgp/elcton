## 明早真机验收（由用户安装，不自动抢前台）

1. 先保留现有课表备份，用户在直装器安装上述同身份 1.1.16 HAP；不要卸载或清数据。手机沿用已装 0.2.9/code11，本轮没有新 APK。
2. 表：周视图 → 同步 → 开始接收；保持该页前台，观察常亮与 SDK/REG 状态。原有首页、周视图、详情、删除和键盘设计不重做。
3. 手机 MCP：`devices_list`，需要刷新时传 `{"refresh":true}`；取响应里的真实 device_id（不凭记忆猜 ID）。
4. `sync_connect`，参数 `{"device_id":"<本次真实ID>"}`；回读 `sync_state`，握手预期 ready=true、busy=false，表看到 HELLO/READY_OK。accepted 只表示动作已接收，不能当完成。
5. 确认本次覆盖方向和手机课表正确后，`start_publish` 参数 `{"confirm":true,"force":false}`；不要默认强制覆盖。继续回读 `sync_state`，以完成事件和表端 APPLIED 判断保存。
6. 需要实际回读表课表时，使用 `start_import` `{"confirm":false}` 后轮询 `sync_state` 的 `import_pending`；完成后读取 `courses_read` 的 `pending_import`（表端回读预览）与 `document`（手机现有课表）逐项比对。`confirm:false` 不写回手机，`accepted:true` 或 `ready:true` 均不代替内容一致。
7. 任一步失败：记录发生时间、表页和末尾阶段；立即拉 elcton 表 logger 与手机 `error_tail` / `diag_read`（必要时加 `version_info`）。本地镜像 `~/.hermes/watchlogs/elcton/`；正文是 `log.msg`，不是 text，按 sid/seq/cursor 区分 HOST 样本与这次真实表会话。
8. logger 手动收集命令：`python ~/lite-watch-logger/tools/fetch-logs.py --app elcton --once`。认证 pull 为 GET `action=pull&app=elcton&after=<cursor>` + `X-Log-Key` read key；凭据私下读取，禁止复制到公开命令/报告。

在真实 FIT3 HELLO→READY→APPLIED 和回读一致之前，不给“握手已修好”结论。新表日志缺失也不直接推断页面未执行（可能队列未发出/网络无回调）。
